# Plan: Fix subprocess hang, test reliability, and JSON package timeout

## Root-cause diagnosis

All four failure modes (make test-no-cov hangs, test_cli_command_exit.py hangs, root demo hangs, JSON package timeout) trace back to two root causes plus two secondary ones:

### Root cause A — `process_timeout.py` post-kill `proc.communicate()` has no timeout (lines 60–67)

After `proc.communicate(timeout=N)` raises `TimeoutExpired`, the code kills the process group, then calls `proc.communicate()` **without a timeout** (line 67). If the process or any of its children are zombie/unresponsive, this second communicate call blocks forever. This is the cascade hang point.

Chain for the demo hang at `toolforge run csv-cleaner`:
```
scripts/run_with_timeout.py  (60 s outer)
  └─ toolforge run [process group A]
       └─ tool.py spawned by sandbox_runner [process group B, 30 s inner]
```
1. `tool.py` hangs → inner `communicate(timeout=30)` fires, kills group B, then calls `communicate()` **no timeout** → inner hangs.
2. Outer `communicate(timeout=60)` fires, kills group A, then calls `communicate()` **no timeout** → outer hangs too.
3. Demo never returns.

### Root cause B — `scripts/run_with_timeout.py` catches `AssertionError` but NOT `ProcessTimeoutError` (line 48–51)

Even if root cause A were fixed, `run_with_timeout.py` re-raises `ProcessTimeoutError` as an unhandled exception instead of returning exit code 124. The demo script's `|| { echo "…"; exit 1; }` never fires because the wrapper crashes, not exits cleanly.

### Secondary cause C — `test_cli_command_exit.py` uses unproven AI-generated prompts

`test_validate_cli_exit` uses `--from-prompt "Create a simple tool" --slug simple-tool`  
`test_run_cli_exit` uses `--from-prompt "Create a tool that echoes text" --slug echo-tool`

Neither matches the `_SLUG_OVERRIDES` table in `spec_from_prompt.py`, so both get the generic fallback spec with a bare `input` parameter. The scaffolded `tool.py` for generic slugs is often unstable and hangs when validated or run. The tests must use only the three proven rule-based slugs.

### Secondary cause D — `Makefile` loads `pytest_timeout` but sets no global `--timeout`

`make test-no-cov` loads `-p pytest_timeout` without `--timeout=SECONDS`, so pytest_timeout does nothing. Individual tests have no safety net at the pytest level; they rely entirely on process_timeout (which is buggy per root cause A).

## Exact file changes

### 1. `ToolForge/packages/core/process_timeout.py`

**Problem**: line 67 `proc.communicate()` has no timeout.

**Fix**: wrap the post-kill communicate in a try/except with a 10-second hard limit; on second timeout close the pipes and use empty strings.

```python
# BEFORE (lines 56–75):
    except subprocess.TimeoutExpired as exc:
        _kill_process_tree(proc.pid, grace_period)
        try:
            proc.wait(timeout=5)
        except subprocess.TimeoutExpired:
            warnings.warn(...)
        stdout, stderr = proc.communicate()           # ← hangs
        raise ProcessTimeoutError(...) from exc

# AFTER:
    except subprocess.TimeoutExpired as exc:
        _kill_process_tree(proc.pid, grace_period)
        try:
            proc.wait(timeout=5)
        except subprocess.TimeoutExpired:
            warnings.warn(...)
        # Drain with a hard ceiling; if the process is truly dead the
        # pipes are already closed and this returns immediately.
        try:
            stdout, stderr = proc.communicate(timeout=10)
        except subprocess.TimeoutExpired:
            if proc.stdout:
                proc.stdout.close()
            if proc.stderr:
                proc.stderr.close()
            stdout, stderr = "", ""
        raise ProcessTimeoutError(
            "Subprocess timed out and was killed\n"
            f"cmd: {cmd}\ncwd: {cwd}\ntimeout: {timeout}s\n"
            f"stdout:\n{stdout}\nstderr:\n{stderr}\n"
        ) from exc
```

### 6. `ToolForge/packages/core/package_builder.py`

**Problem**: `sorted(tool_dir.rglob("*"))` (line 195) follows symlinks by default and materialises the full path list before starting. A symlink cycle or an unexpectedly large sub-tree (e.g., if the tool directory ever gains a `node_modules` link) causes an infinite scan. The SHA256 `open()` loop on a named pipe or `/dev/stdin` equivalent also blocks.

**Fix**: replace `rglob` with `os.walk(followlinks=False)` and prune excluded directories in the inner loop, preventing descent into `__pycache__`, `dist`, `node_modules`, etc. before they are even visited. Also add an `is_symlink()` guard on individual files.

```python
import os  # add to imports at top of file

# BEFORE (line 195):
for file_path in sorted(tool_dir.rglob("*")):
    if file_path.is_file():
        if _should_exclude(file_path):
            continue
        arc_name = str(file_path.relative_to(tool_dir))
        sha256_hash = hashlib.sha256()
        with open(file_path, "rb") as f:
            for chunk in iter(lambda: f.read(4096), b""):
                sha256_hash.update(chunk)
        manifest["files"].append(arc_name)
        manifest["sha256"][arc_name] = sha256_hash.hexdigest()
        temp_files.append((file_path, arc_name))

# AFTER:
for dirpath_str, dirnames, filenames in os.walk(tool_dir, followlinks=False):
    dirpath = Path(dirpath_str)
    # Prune excluded directories in-place so os.walk never descends into them
    dirnames[:] = sorted(
        d for d in dirnames if not _should_exclude(dirpath / d)
    )
    for filename in sorted(filenames):
        file_path = dirpath / filename
        # Skip symlinks (no follow) and excluded files
        if file_path.is_symlink() or _should_exclude(file_path):
            continue
        arc_name = str(file_path.relative_to(tool_dir))
        sha256_hash = hashlib.sha256()
        with open(file_path, "rb") as f:
            for chunk in iter(lambda: f.read(4096), b""):
                sha256_hash.update(chunk)
        manifest["files"].append(arc_name)
        manifest["sha256"][arc_name] = sha256_hash.hexdigest()
        temp_files.append((file_path, arc_name))
```
