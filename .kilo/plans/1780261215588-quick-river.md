# Smoke Release Candidate Repair Plan

**Date**: 2026-05-31
**Scope**: Fix release-gate drift, unify hygiene policies, and make the smoke release candidate self-verifying

## Problem Summary

The codebase has real structure, real validation artifacts, and real test coverage. The core systems (ToolForge, Agent Skills, Toolathlon GYM) are functional. The release discipline is close to self-verifying but has five categories of contradictions that would break stricter CI gates.

## Phase 1: Unify Release Policy Definitions

### 1.1 Separate release ZIP policy from evidence ZIP policy

**Problem**: `verify_evidence_bundle.sh` uses `EVIDENCE_BUNDLE=1` to select evidence policy from `.release-config/forbidden_entries_evidence.txt`, but the evidence ZIP stores logs under `.validation_logs/` which the release policy forbids. The evidence config correctly omits `.validation_logs` but the shell script applies a second forbidden check before the evidence-policy branch.

**Files to modify**:
- `scripts/verify_evidence_bundle.sh` (lines 12-19)

**Action**: Verify the evidence policy branch correctly uses `EVIDENCE_BUNDLE=1` and that `release_forbidden_entries.sh` properly selects `forbidden_entries_evidence.txt`. The `.release-config/forbidden_entries_evidence.txt` file already correctly omits `.validation_logs` and `release_artifacts/validation_logs`. The script is correctly sourcing with `EVIDENCE_BUNDLE=1`. No change needed — but verify it works by running the script against the evidence ZIP after fixing other issues.

### 1.2 Unify hygiene checkers — one canonical policy

**Problem**: `check_source_bundle_hygiene.py` passes on the canonical release ZIP, but `verify_source_bundle_hygiene.sh` fails because it requires `RELEASE_STATUS.json`, `RELEASE_MANIFEST.json`, and `CLAIMS_MATRIX.md` as required layout paths.

**Root cause**: The Python checker only validates forbidden entries (no traversal, no cache dirs). The shell checker additionally validates required layout paths and structural fields.

**Decision**: The shell checker is the correct superset. The Python checker should be treated as a fast "forbidden entries only" pre-check, and the shell checker as the full gate. We need to:
1. Add `RELEASE_STATUS.json`, `RELEASE_MANIFEST.json`, and `CLAIMS_MATRIX.md` to `build_pruned_smoke_release.py`'s INCLUDE list
2. Document the relationship between the two checkers

**Files to modify**:
- `scripts/build_pruned_smoke_release.py` — Add `RELEASE_STATUS.json`, `RELEASE_MANIFEST.json`, `CLAIMS_MATRIX.md` to INCLUDE list (lines 15-28)
- `scripts/check_source_bundle_hygiene.py` — Add a doc comment clarifying it is a "fast forbidden-entries-only pre-check" and that `verify_source_bundle_hygiene.sh` is the full gate
- `scripts/verify_source_bundle_hygiene.sh` — Add a doc comment clarifying it is the canonical full gate

### 1.3 Fix canonical release contents

**Problem**: The canonical release ZIP does not include `RELEASE_STATUS.json`, `RELEASE_MANIFEST.json`, or `CLAIMS_MATRIX.md`, but the shell hygiene checker requires them.

## Risks and Mitigations

- **Risk**: Rebuilding the canonical release ZIP changes the SHA256 hash, requiring all docs to be updated.
  - **Mitigation**: Phase 1 changes are additive (adding files to INCLUDE). The hash will change, but doc updates in Phase 2 will handle this.
- **Risk**: Toolathlon task-smoke requires PostgreSQL for `rail_12306`, which may not be available.
  - **Mitigation**: Implement graceful degradation — fall back to import-smoke with a warning if the database is unavailable.
- **Risk**: npm audit finds critical vulnerabilities that cannot be patched.
  - **Mitigation**: Document them as known risks and quarantine the servers to disposable containers only. Update SECURITY.md accordingly.
