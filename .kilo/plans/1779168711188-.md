## Gaps Identified

### Gap 1 — `test_helpers.py::run_toolforge` still uses plain `subprocess.run`

**File:** `ToolForge/apps/cli/toolforge_cli/test_helpers.py:86`

`run_toolforge()` uses `subprocess.run(timeout=120)`. When the timeout fires,
Python kills only the **direct child process** and then tries to drain stdout/stderr
pipes via `proc.communicate()`. If any grandchild inherited the pipe file
descriptors (e.g., from `sandbox_runner` level 0/1) and is still alive, the
`communicate()` call blocks waiting for EOF—causing the **test to hang for the
remainder of the timeout or indefinitely**.

The correct pattern (`run_with_process_tree_timeout`) is already used everywhere
else in the codebase (`test_cli_command_exit.py`, `_runner.py`, `_process.py`,
`test_validator.py`, `sandbox_runner.py` level 2). `test_helpers.py` is the one
remaining exception.

**Used by:** `tests/test_cli_validation_regressions.py`

---

### Gap 2 — `scripts/run_with_timeout.py` imports from the `tests` package

**File:** `scripts/run_with_timeout.py:14`

```python
from tests.e2e_scripts._timeout import run_with_process_tree_timeout
```

`_timeout.py` is a thin re-export:
```python
from packages.core.process_timeout import run_with_process_tree_timeout
```

The indirection through `tests.e2e_scripts` is fragile:
- `tests/e2e_scripts/` has **no `__init__.py`** (rely on Python namespace packages).
- The demo script is not a test and should not depend on the `tests` package layout.
- If `tests/` is renamed, moved, or excluded from an install, the demo breaks.

The fix is to import directly from `packages.core.process_timeout`.

---

### Gap 3 — `tests/e2e_scripts/` has no `__init__.py`

**Directory:** `ToolForge/tests/e2e_scripts/`

The directory is importable via Python 3.3+ namespace packages, but having an
explicit `__init__.py` is the correct convention for an intentional Python package
and avoids edge cases with some IDE tooling, coverage, and type checkers.

### Gap 4 — Timeout race in `scripts/demo_csv_cleaner.sh` — validate step

**File:** `scripts/demo_csv_cleaner.sh:56`

```bash
run_with_timeout 60 toolforge validate csv-cleaner
```

The outer demo timeout is **60 s**. Inside `toolforge validate`, `test_validator.py`
also uses `run_with_process_tree_timeout(timeout=60)` for the nested pytest run.
If the nested pytest takes 55 s (not unusual for first-run tool generation + test
collection), the outer 60 s fires first, `run_with_timeout.py` kills `toolforge
validate`, and the demo exits 1 with "Validate failed"—even though the command
would have succeeded if given 5 more seconds.

Fix: increase the validate step's outer timeout to 120 s.

The same race can occur for `new tool` (step 2, 120 s is fine) and `run` (step 5,
60 s is fine since tool execution is fast). Only `validate` is at risk.

## Changes to Implement

### Change 1 — Upgrade `test_helpers.py::run_toolforge`

**File:** `ToolForge/apps/cli/toolforge_cli/test_helpers.py`

Replace the `subprocess.run(timeout=timeout)` call with
`run_with_process_tree_timeout`. Keep the existing public API unchanged
(`args`, `cwd`, `timeout`, `env` kwargs; returns `subprocess.CompletedProcess`).

```diff
-import subprocess
+import subprocess
 ...
+from packages.core.process_timeout import ProcessTimeoutError, run_with_process_tree_timeout

 def run_toolforge(args, *, cwd, timeout=120.0, env=None):
     effective_env = os.environ.copy()
     if env:
         effective_env.update(env)
     cmd_prefix, _, cleaned_env = build_toolforge_command(effective_env)

-    result = subprocess.run(
-        [*cmd_prefix, *args],
-        cwd=str(cwd),
-        text=True,
-        capture_output=True,
-        timeout=timeout,
-        env=cleaned_env,
-        check=False,
-    )
-    return result
+    try:
+        result = run_with_process_tree_timeout(
+            [*cmd_prefix, *args],
+            cwd=Path(cwd),
+            env=cleaned_env,
+            timeout=timeout,
+        )
+    except ProcessTimeoutError:
+        return subprocess.CompletedProcess(
+            args=[*cmd_prefix, *args],
+            returncode=124,
+            stdout="",
+            stderr="[toolforge test helper] command timed out",
+        )
+    return result
```

Note: `run_with_process_tree_timeout` already returns a `subprocess.CompletedProcess`
so the return type is unchanged.
